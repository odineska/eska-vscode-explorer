# Запросы в Designer XML и BSL

Во временной вкладке Explorer показывает SDBL без XML-экранирования и
служебных символов BSL-строки. Дополнительный файл `.sdbl` в проекте не
создаётся. Права запроса учитывают разрешения файловой системы, правила
поддержки 1С и настройки `files.readonlyInclude` и `files.readonlyExclude`.
Если исходник доступен только для чтения, запрос открывается для просмотра.

В дереве раскройте макет СКД, затем набор данных типа «Запрос» и строку
**Запрос**. Для формы раскройте реквизит ручного динамического списка и его
запрос. Автоматический список без сохранённого текста запроса пропустите.

## Литерал BSL

Поставьте курсор внутри цельного строкового литерала и выберите
**Открыть запрос отдельно** в контекстном меню. Имя переменной может
быть любым. Конкатенации, шаблоны и вычисляемые выражения не поддерживаются.

Если модуль закрыт для редактирования правилом `files.readonlyInclude`,
запрос наследует ограничение. Разрешите редактирование запроса на текущий
сеанс штатной командой VS Code. При сохранении Explorer снимет тот же
пользовательский запрет у модуля, чтобы перенести правку. Настройки VS Code
и правила поддержки 1С продолжают действовать для остальных файлов.

## Сохранение и закрытие

Нажмите **Ctrl+S** во вкладке запроса, чтобы перенести текст в исходный XML
или модуль BSL. Меняется выбранный запрос. Вкладка остаётся открытой и
принимает дальнейшие правки. Нажмите **Ctrl+S** ещё раз для их сохранения.
Представления одного запроса в разделённом редакторе используют общий текст.
Explorer открывает новую вкладку запроса в UTF-8, в том числе при глобальной
настройке Windows-1251. При сохранении исходник сохраняет свою кодировку
и переводы строк. Настройки форматирования при сохранении применяются
к вкладке запроса. Чтобы отформатировать весь модуль или XML, сохраните
вкладку самого исходника с включённым форматированием.

Если исходник был сохранён, изменения запроса сохраняются и на диск.
Если в исходнике уже были несохранённые правки, они остаются в буфере
вместе с обновлённым запросом. Чтобы записать весь файл, сохраните вкладку
самого исходника. Открытие запроса сохраняет несохранённый буфер владельца
в редакторе.

При закрытии вкладки действует обычный выбор редактора для несохранённых
правок. После закрытия Explorer возвращает исходник. Если отменить закрытие,
работу можно продолжить в той же вкладке.

Если VS Code восстановил вкладку запроса после перезапуска, **Ctrl+S**
проверяет состояние исходника перед записью. При конфликте или отказе в
записи прочитайте сообщение Explorer. Текст запроса остаётся во вкладке.
При необходимости скопируйте его перед закрытием.

Если исходный комментарий нельзя перенести однозначно, команда **Назначить
позиции исходных комментариев** позволяет выбрать место, автоматический
перенос или явное удаление. Позицию `строка:столбец` указывают с единицы.
Для комментария между строками BSL можно выбрать начало следующей строки
запроса. После выбора повторите сохранение.

## Анализ BSL-черновика

С Metadata API 1.20 и опубликованным `bsl-analyzer-app` 0.4.0 BSL-черновик
анализируется в текущем приложении. ESKA собирает в памяти полный модуль с новым
запросом и переводит позиции и правки; расширение использует уже работающий LSP.
Дополнительный файл, процесс или индекс на каждую правку не создаётся.

Проверены подсказки полей метаданных, псевдонимов и полей временных таблиц из
предыдущих запросов того же пакета, а также обновление диагностик синтаксиса.
Принятие подсказки меняет только SDBL-черновик. Hover, переход к определению и
ссылки передаются серверу; их покрытие определяется опубликованным анализатором.
Правки вне выбранного литерала, команды и snippets от completion не выполняются.

Статус во вкладке различает работающий BSL-контекст, построение индекса,
ограниченный самостоятельный контекст, приостановку и недоступный отчёт.
Пустой ответ во время загрузки не принимается за завершённую проверку.
Подсказки параметров запроса и контекст XML-владельцев в проверенном контракте
недоступны. СКД, основная таблица и зависимые поля списка остаются непроверенными.

Обычные языковые запросы к модулю-владельцу временно приостановлены: его позиции
могут отличаться от проекции. Другие BSL-модули продолжают анализироваться.
При изменении обычной вкладки владельца анализ черновика приостанавливается,
а LSP снова получает актуальный native-буфер. Отмена, применение и перезапуск
также восстанавливают обычную синхронизацию. Прежние ответы отбрасываются.
Смена приложения не переносит чужой resolver в ранее открытый черновик.

## Конструктор

В SDBL-вкладке выберите **Конструктор запросов**. Для выбора метаданных и
базовых структурированных операций нужен Metadata API 1.22, для возможностей
ниже — 1.23. API 1.21 сохраняет прежнее
редактирование выражений без каталога. Компоновка повторяет привычную схему
Конфигуратора: вкладки сверху, рабочие панели в центре, **Запрос**, **Назад**,
**Далее**, **ОК**, **Отмена** снизу. Все вкладки, доступные backend, видны сразу;
в узком окне они переносятся на следующую строку. Цвета, шрифты, выделение,
кнопки, поля и таблицы берутся из текущей темы VS Code и меняются вместе с ней.
Те же базовые элементы используются в свойствах и preview переименования.

Разделы конструктора:

- **Таблицы и поля**: слева база данных с поиском, в центре выбранные таблицы
  и их поля, справа поля результата. Двойной щелчок по таблице добавляет её
  в источники, по полю — в результат. Можно выделить таблицу или поле и нажать
  стрелку переноса между панелями; обратная стрелка удаляет выбранные элементы.
  Кнопка с двойной стрелкой добавляет все поля выбранного источника. **Добавить все поля** выполняется одной
  операцией и пропускает уже выбранные поля. Разворачивание таблицы показывает
  её табличные части; ESKA читает только запрошенный дескриптор.
  У регистра также доступны виртуальные таблицы; при выборе появляются
  позиционные параметры из сигнатуры ESKA, включая подсказки периодичности
  и метода дополнения. Пустое необязательное значение сохраняет свою позицию.
  **Добавить вложенный запрос** создаёт источник; его редактирование переводит
  ту же панель в дочернюю область. Родитель доступен после явного возврата.
- **Связи**: общая таблица показывает левую и правую стороны, вид соединения
  и выражение. Вид меняется прямо в строке; псевдоним, поля и сравнение задаются
  в редакторе выражения. Изменение вида соединения сохраняет комментарии заголовка.
- **Группировка**: поля группировки и суммируемые поля с выбором агрегатной функции.
- **Условия**: левое поле, сравнение и правое значение/выражение показаны
  отдельными колонками. Несколько
  условий соединяются через `И`/`AND`.
- **Дополнительно**: `РАЗЛИЧНЫЕ/DISTINCT`, `РАЗРЕШЕННЫЕ/ALLOWED`,
  `ПЕРВЫЕ/TOP`, автоупорядочивание и блокировка. Здесь же раскрывается секция
  **СКД**. Изменение настроек проходит через preview Rust перед подтверждением.
- **Порядок**: поле/выражение и направление сортировки, отдельными колонками.
- **Объединения и псевдонимы**: копия выбранной ветки, переключение веток,
  сохранение/исключение дублей и удаление ветки. Выходные колонки добавляются,
  удаляются и переставляются согласованно; отсутствующее новое значение
  заполняется `NULL`. Порядок и итоги принадлежат всему объединению.
- **Индексы**: индексные выражения временной таблицы текущего запроса.
- **Пакет запросов**: дерево запросов, временных таблиц и вложенных областей.
- **Текст запроса**: полный текст, редактирование через проверяемый preview,
  сравнение с исходным текстом и переходы по комментариям.
- **Итоги**: агрегатные выражения, общие итоги, группировки с иерархией
  либо заполнением периодов. Пустой список выражений означает автоматические
  итоги; удаление последней группировки убирает всю секцию.

Каталог использует выбранное приложение ESKA и объединяет объявления базы и
входящих расширений. Другие приложения не подмешиваются. Имена пользовательских
полей сохраняются, стандартные поля предлагаются в языке исходного запроса.
Бухгалтерский регистр с корреспонденцией получает раздельные счета и небалансовые
измерения/ресурсы дебета и кредита. Нумерованные субконто не приписываются обычной
таблице регистра. Без явно заданной базы внешний объект показывает ограниченный контекст.

Псевдоним нового источника при пустом вводе выбирает ESKA. При переименовании
существующего источника ESKA обновляет доказуемые ссылки, сохраняя строки,
комментарии и пути метаданных. Источники без `КАК`/`AS` используют полную квалификацию.
Для сложной строки доступно **Редактировать выражение**.
Регистры расчёта получают ресурсы графика и доступные базы через назначенные
планы видов расчёта. Переименование доказанного выходного поля обновляет ссылки
родителей и общий хвост; строки, комментарии и затенённые области сохраняются.
Порядок соединений по-прежнему не меняется без проверки зависимостей.

Разбор, допустимость операции, перенос комментариев и генерация минимальной
правки выполняются ESKA. Несовпадение числа полей веток блокирует применение
изменённого запроса. `ПОМЕСТИТЬ/INTO`, временные таблицы, `ИМЕЮЩИЕ/HAVING`
и поддержанные секции СКД доступны через операции, описанные ниже. Неизвестные
операторы, несколько последовательных секций итогов и другие неподдержанные
конструкции сохраняются точным исходным текстом с объяснением недоступности. Полный пакет доступен в **Текст запроса**.
Конструктор проверяет структуру поддержанных изменений. BSL-владельцам доступен
анализатор через существующий языковой мост, но полная семантика выражений,
вывод типов и предложения связей всего конструктора пока не завершены upstream.
Структурная проверка текста не заменяет их или выполнение запроса в ИБ.
Вложенные области не получают общего порядка и итогов. Для старых API составные
запросы остаются непрозрачным текстом без новых операций.

Комментарии перемещаются с узлом. Перед удалением узла с комментарием нужно
выбрать перенос к оставшейся границе или удаление вместе с узлом. Отмена выбора
сохраняет предыдущий текст. Открытие и применение без операций сохраняют текст
и форматирование, включая неподдержанные части пакета.

Пока открыт конструктор, редактируемые вкладки запроса заменяются его панелью.
Нажмите **ОК**, чтобы вернуться к вкладке запроса с результатом. В этой
вкладке нажмите **Ctrl+S**, чтобы сохранить результат в исходнике.
**Отмена** или закрытие панели возвращают текст, с которым вы открыли
конструктор. Запрос, доступный только для чтения, можно открыть для просмотра.

Ролик показывает сохранение изменённого запроса через **Ctrl+S** и возврат
в модуль после закрытия вкладки.

Историческая приёмка T104 выполнена в установленном VSIX на Linux/VSCodium в ru/en: шесть разделов,
opaque-части пакета, комментарии, один Undo/Redo, dirty XML/BSL, read-only,
авария backend и настоящие кнопки webview. Выбор в диалогах комментариев в стенде
задан скриптом. Windows, macOS, VS Code и Remote остаются непроверенными.

Панели конструктора имеют изменяемую ширину, раскрытый текст — изменяемую
высоту. Разделители работают мышью и клавишами: Влево/Вправо для панелей,
Вверх/Вниз для текста. На узком окне каталог скрывается и возвращается кнопкой
**База данных**. Между вкладками можно переходить кнопками **Назад**/**Далее**
или стрелками клавиатуры, когда фокус находится на вкладке. Размеры, раскрытие и прокрутка сохраняются в пределах
открытого конструктора, включая возвращение из вложенной области. Обновление
метаданных сохраняет ввод и курсор; состояние компоновки не содержит второй
копии текста запроса. Базовая компоновка работает с API 1.30; новые табличные
действия требуют API 1.31, инструменты ниже — API 1.32.

### Пакет и временные таблицы (API 1.26)

На вкладке **Пакет** укажите назначение `ПОМЕСТИТЬ/INTO`, добавьте запрос
или `УНИЧТОЖИТЬ/DROP`, удалите либо переставьте оператор. Пустое назначение
возвращает обычный результат. Поля индекса задаются списком `INDEX BY`.
Созданные ранее временные таблицы появляются в каталоге с проекцией создающего
запроса; поддержаны объединения, вложенные потребители и раскрываемые `*`.
После уничтожения прежняя проекция недоступна. Переименование сохраняет явные
псевдонимы и не затрагивает следующее создание одноимённой таблицы.

ESKA определяет области, время жизни и доказуемые зависимости; расширение
передаёт намерения и показывает результат. Новая известная ошибка отклоняет
всю операцию. Применение и отмена используют тот же черновик и штатный Undo/Redo.
`INDEX BY SETS` и `UNIQUE` сохраняются непрозрачными; добавление строк
в существующую временную таблицу пока вне визуального набора.

### Отбор по агрегатам (API 1.27)

На вкладке **Условия** есть отдельный раздел **Отбор по агрегатам (ИМЕЮЩИЕ)**.
Задайте выражение, сравнение и значение. ESKA создаёт `HAVING` после группировки,
различает ветки объединения и вложенные области; условия до группировки остаются
в прежнем `WHERE`. Доступны изменение, перемещение и удаление условий с прежними
правилами комментариев. Применение и отмена работают с тем же черновиком.

### Секция итогов и уровни группировки (API 1.30)

На вкладке **Итоги** добавьте секцию и задайте выражения и группировки.
Поддерживается одна секция с несколькими уровнями: платформа 8.3.27 отклоняет
повторное `ИТОГИ/TOTALS`. Добавление второй секции недоступно. Удаление последней
группировки убирает секцию, а пустой список агрегатов оставляет автоматические
итоги. Сохраняются общие итоги, иерархия, периоды и комментарии. ESKA вычисляет
владельцев строк и разрешения; расширение использует полученные индексы.
Несколько секций в исходном тексте сохраняются дословно без визуальной правки.

С API 1.29 вкладка «СКД» показывает узлы, позиции и разрешения ESKA. Поля,
дочерние поля, псевдонимы и бинарные условия передаются как значения DTO;
JavaScript не собирает фигурные скобки и запросы. Можно переключать
необязательность существующего JOIN и условность параметра периода виртуальной
таблицы, менять её отбор. Неизвестные блоки сохраняются. Обычные секции запроса
с расширениями СКД доступны только для чтения; основной текст меняется в
черновике после закрытия конструктора. Полную семантику проверяет платформа 1С.

### Таблицы и связанные инструменты (API 1.31/1.32)

Выберите строки флажками или диапазоном Shift. Общая панель копирует, удаляет
и перемещает набор; Alt+↑/↓, Delete и Ctrl/Cmd+D дают те же действия. Двойной
щелчок или Enter/F2 открывает ячейку, Enter принимает ввод, Escape отменяет.
ESKA выполняет действие атомарно, выделяет псевдонимы и согласует UNION.

Группы условий поддерживают И/ИЛИ/НЕ, МЕЖДУ и NULL; ON каждого JOIN редактируется
отдельно, перенос WHERE/HAVING явный. Матрица UNION показывает позиции колонок
и ветви; выравнивание `NULL` и перенос колонки требуют подтверждения preview.
Дерево пакета показывает вложенные области, а переход временной таблицы ведёт
к её текущему определению. Копирование оператора выделяет новое имя назначения.
В параметрах виртуальной таблицы сохраняются пустые позиционные аргументы.

**Настройки запроса** меняют DISTINCT, ALLOWED, TOP, AUTOORDER и доступный
FOR UPDATE через preview. Меню **Текст** открывает diff, комментарии и отдельный
буфер полного текста. **Показать в тексте** и двойной щелчок в тексте связывают
строку модели с её диапазоном. Ошибочный ввод остаётся в буфере для исправления;
подтверждённый preview публикует одну ревизию. Диалог блокирует ввод в родителе,
отмена не меняет запрос. Команды старой ревизии отклоняются.

Преобразования, диапазоны, комментарии и проверки принадлежат ESKA. Полная
семантика, типы, языковые сервисы и подтверждённый подбор связей ожидают
bsl-analyzer. Структурная проверка полного текста ими не является. Сервер со
старыми capabilities сохраняет прежние действия и скрывает новые инструменты.


### Проверка интерфейса с Solid

Редизайн проверен 2026-11-02 на Linux ARM64: VS Code 1.109.0 (`en`) и
1.144.0 (`ru`), отдельные профили XWayland. Проверены metadata, вложенные запросы,
виртуальные таблицы, WHERE/HAVING, настройки выборки и preview, таблицы, UNION,

Компоновка проходит тёмную, светлую и контрастную темы, два размера окна и

без Analyzer, не гарантия для любой конфигурации или машины.
