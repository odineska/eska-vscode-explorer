# Работа с деревом eska

Подробности навигации, поиска, фильтра и диагностики. [Краткое руководство](../README.md).

## Подключение

1. Откройте папку с `eska.toml` в доверенной рабочей области.
2. Укажите `eska-project` с Metadata API 1.12 или новее в `eska.explorer.executable`.
   Прежний `eska ide` выбирается явно через `eska.explorer.backend = "legacy"`.
   [Выбор и обновление backend](cli-management.md). Аргументы в пути не поддерживаются.
3. Раскройте представление **ESKA: 1C Explorer** в проводнике VS Code.

Команды **ESKA Explorer** позволяют выбрать проект, перезапустить или отключить
подключение и открыть журнал. Из нескольких независимых папок VS Code выбирается
одна. Если это корень workspace eska, backend открывает его участников по
существующим правилам `eska.toml`. При переключении папки старый процесс сначала
завершается. Повторные попытки после ошибки выполняются по команде пользователя.

Версия подключённого сервера отображается справа в строке состояния: `ESKA Project v<version>` (либо `ESKA Legacy v<version>`).
При отключении индикатор скрывается. Перезапуск подключения доступен в панели
Explorer; выбор проекта, отключение и журнал — в меню More Actions (`…`).

Горячие клавиши подключённого проекта:

| Действие | Windows / Linux | macOS |
| --- | --- | --- |
| Показать открытый файл в дереве eska | `Ctrl+K`, затем `E` | `Cmd+K`, затем `E` |
| Поиск по дереву | `Ctrl+K`, затем `F` | `Cmd+K`, затем `F` |
| Обновить дерево (фокус в дереве eska) | `F5` | `F5` |

Буква после первой комбинации нажимается без модификаторов. Сочетания перехода
и поиска переопределяют стандартные команды только при фокусе в редакторе файла
подключённого проекта; поиск также доступен при фокусе в дереве eska.
В остальных проектах стандартные сочетания сохраняются. Настроить или удалить
назначения можно в Keyboard Shortcuts по фильтру `ESKA Explorer`.
Переход раскрывает нужную ветку без полной индексации, не меняет открытый файл
и его несохранённые правки. Для файла без соответствия выводится уведомление.

Если manifest отсутствует, показывается [инструкция настройки](setup.ru.md).
Расширение не запускает `eska-project init` автоматически.
Изменение настройки пути отключает прежнее подключение; затем используйте команду
перезапуска. Изменение `eska.toml` автоматически переподключает текущий контекст. Точные файлы
manifest проекта и его родителей проверяются раз в секунду, включая первоначально
отсутствующие файлы и исключённые в VS Code папки. После `eska add ssl_3_1`
открытый отчёт или обработка получает библиотечный контекст без перезапуска окна;
несохранённые BSL-буферы сохраняются.

### Настроить проводник перед работой

1. Откройте в VS Code папку с `eska.toml`, а не только вложенную `src`.
   Для готовой XML-выгрузки без manifest сначала выполните
   `eska-project init ./my-project --source src`.
2. В **Проводнике** перетащите заголовок **ESKA: 1C Explorer** выше остальных групп.
3. Сверните обычное дерево файлов, **Структуру** и **Временную шкалу** нажатием
   на их заголовки. Это только настройка расположения панелей VS Code.
4. Раскройте **ESKA: 1C Explorer** и нужные разделы метаданных. Если подключения
   нет, выполните команду **Выбрать проект и подключиться**.

Скринкаст показывает расположение панели в открытом проекте.

[![Настроить проводник — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11-18/explorer-setup.gif)](https://odineska.tech/eska/docs/#demo-setup)

## Создание, копирование и удаление объектов

Для этих действий нужен подключённый `eska-project` с Metadata API 1.49 и
доверенный workspace. Команды доступны в палитре **ESKA Explorer** и меню дерева:

- **Добавить…** — у группы или владельца. Выбранная группа определяет тип и
  владельца: **Реквизиты** добавляет реквизит, **Формы** — форму. У корня или
  владельца сначала выбирается допустимый вид из схемы backend.
- **Копировать объект метаданных…** — полная копия выделенного объекта или формы у того же
  владельца. Копируются вложенные реквизиты, формы, модули и двоичные ресурсы;
  собственные UUID создаются заново, внутренние ссылки корректируются.
- **Удалить объект метаданных…** — удаление объекта вместе с принадлежащими ему файлами
  после просмотра найденных ссылок. Ссылки из других объектов и исходников
  автоматически не удаляются.

При создании вводятся имя и обязательные параметры. Остальные значения имеют
платформенные значения по умолчанию и редактируются в панели свойств. Типы,
ссылки и стандартные значения выбираются из общих списков backend с поиском
и локализованными названиями. Для создания по образцу используйте копирование.
Ошибка допускает исправление имени или свойства с сохранением введённых значений.

С Metadata API 1.50 **Добавить…** у владельца или группы **Модули** предлагает
отсутствующие роли: например, у документа только модуль объекта и модуль менеджера.
Существующий BSL или двоичный модуль не заменяется. Имя и путь задаёт роль,
собственный UUID модулю не выделяется. Созданный модуль открывается в редакторе.

Обычное добавление выполняется после ввода обязательных значений. Копирование
и удаление требуют подтверждения: вкладка показывает файлы, размеры до/после,
новые UUID и найденные ссылки.
Для удаления с найденными ссылками кнопка явно называется **Удалить, оставив
ссылки**. Кандидаты в BSL и подтверждённые ссылки отмечены отдельно.
Закрытие вкладки и **Отмена** не меняют исходники.

Во время расчёта плана и записи отображается отдельный индикатор прогресса.
Ввод значений и просмотр операции выполняются вне этого индикатора; начавшаяся
запись не предлагает отмену и не повторяется автоматически.
Перед записью повторно проверяются изменившиеся файлы, несохранённые буферы
входных исходников, настройки запрета редактирования и правила поддержки.
Неподтверждённая запись после разрыва соединения никогда не повторяется
автоматически. Сначала обновите дерево и проверьте результат. Автоматической
отмены структурной операции нет; обычные средства Git остаются доступны.
В рабочем пространстве с несколькими проектами контекстное действие сохраняет
выбранного владельца. Создание из палитры без выбранного узла предлагает проект.

После создания или копирования объект выделяется в дереве. Для целой формы
открывается существующий просмотрщик, для другого объекта — свойства.
Новые управляемые формы создаются через общее ядро; изменение элементов,
данных, команд и событий доступно через CLI `metadata form-schema` /
`metadata form-edit` и [в основной вкладке формы](form-preview.md#интерактивное-редактирование) с Metadata API 1.53.
Копирование формы к другому владельцу и редактирование обычных двоичных форм
не поддержаны; двоичные ресурсы целого копируемого объекта сохраняются.

Команды меняют только Designer XML и связанные исходники. Обновление тестовой
базы выполняется отдельно. Виды, недоступные выбранному владельцу, не предлагаются;
ограничения проекта и поддержки проверяет backend перед применением.

## Дерево и исходники

Контекстная команда **Открыть в новой вкладке** открывает модуль, отдельный
исходник формы или файл проекта в закреплённой вкладке текущей группы.
Обычный клик сохраняет предварительный просмотр. Ограничения поддержки
применяются одинаково.

Во вкладке модуля конфигурации или расширения показывается полное имя 1С,
например `Документ.ВыдачаЗайма.МодульМенеджера`. VS Code подставляет имя по
пути Designer XML и использует язык интерфейса редактора. У корневых модулей
конфигурации подпись включает расширение, например `Конфигурация.МодульСеанса.bsl`.
Для модулей внешних отчётов и обработок отображается имя файла. Свои подписи можно
задать в `workbench.editor.customLabels.patterns`.

[![Найти объект и открыть модуль — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11-18/explorer-tree.gif)](https://odineska.tech/eska/docs/#demo-tree)

Порядок и подписи групп задаёт backend по типу проекта: конфигурация,
расширение, внешний отчёт или обработка. Ветки загружаются при раскрытии;
пустые разделы корня и разделы внутри «Общие» скрыты по умолчанию.

У корня каждой конфигурации и расширения есть кнопка фильтра: **Показывать пустые
группы / Скрывать пустые группы**. Скрываются только подтверждённо пустые разделы
корня (например, «Константы») и непосредственные разделы внутри «Общие»
(например, «Роли»). Незагруженные и ошибочные ветки остаются; группы внутри объектов,
например «Формы» справочника, не фильтруются.
«Общие» видно, если заполнена хотя бы одна вложенная группа. Внешние отчёты и
обработки не фильтруются, кнопки у них нет. Группу модулей без существующих BSL
backend не создаёт независимо от фильтра, в том числе при наличии только `.bin`.

Настройка **Eska › Explorer: Hide Empty Root Groups**
(`eska.explorer.hideEmptyRootGroups`, по умолчанию `true`) задаёт исходный режим.
Приоритет: явный выбор проекта → настройка папки → workspace → user → умолчание.
Выбор кнопкой хранится отдельно для каждого проекта в `workspaceState` VS Code
и переживает перезапуск IDE; он не записывается в `eska.toml` или исходники.
Контекстное действие **Использовать фильтр по умолчанию** снимает выбор проекта
и возвращает применение настройки, включая её последующие изменения.

Переключение использует готовые состояния backend и кеш ветвей, не переиндексирует
проект и не разбирает XML повторно. Раскрытие сохраняется; если выбранная группа
или её родитель скрывается, выделяется корень проекта без переноса фокуса из
редактора. Добавление/удаление последнего объекта меняет видимость раздела после
обычного обновления файлов.

«Модули» расположены первыми и изначально свёрнуты. После ручного сворачивания
группа остаётся свёрнутой при обновлении ветки в текущем сеансе расширения.
Показываются только существующие BSL; двоичные модули без BSL скрыты.
Общие модули, команды, боты, WebSocket-клиенты, HTTP/Web-сервисы, сервисы
интеграции и перерасчёты открывают свой BSL по нажатию на имя, без группы
«Модули». Вложенные шаблоны URL, методы, операции, параметры, каналы и измерения
сохраняются. Контекстное меню **Открыть XML** открывает описание объекта.
Если BSL отсутствует (например, есть только `.bin`), объект остаётся доступен
для просмотра: клик открывает свойства, **Открыть XML** — описание.

У форм отдельные дочерние узлы **Форма** (содержимое `Ext/Form.xml`) и **Модуль**
(BSL), только при наличии соответствующих файлов. Подписи следуют настройке
языка дерева. Клик по названию общей формы или формы объекта всегда открывает её свойства.
XML описания доступен через контекстное меню. Список источников
загружается при раскрытии формы,
кешируется до изменения ветки и обновляется при изменении файлов.
Для модулей перерасчёта нужен backend с поддержкой отдельных descriptors
`Recalculations/<имя>.xml` и `Ext/RecordSetModule.bsl`.

У справочников, планов счетов, планов видов характеристик и планов видов расчёта
после группы «Стандартные реквизиты» расположены **Предопределённые данные**. Элементы и вложенные
группы загружаются из `Ext/Predefined.xml` при раскрытии. Выбор элемента открывает
свойства; **Открыть XML** выделяет его имя в исходнике. Поиск находит имя и описание.
Изменения файла обновляют дерево и поиск. Пустая группа остаётся видимой,
как остальные внутренние группы.
Нужен backend с поддержкой `predefined-item`; редактор данных не добавлялся.

У объектов с платформенными реквизитами есть группа **Стандартные реквизиты**.
Начиная с ESKA 0.38.0 в исходном порядке дерева она идёт сразу за группой
«Модули». Если модулей нет, она идёт первой.
Она показывает поля даже без записанного в XML блока настроек: ссылку, код,
наименование, дату, номер, поля регистров и другие реквизиты владельца.
Как в Конфигураторе, настройки неиспользуемого поля остаются видимыми, например
код длиной `0` и родитель неиерархического справочника. Выбор реквизита открывает
его собственные свойства и тип. Группа предназначена только для просмотра:
создание, переименование, удаление и переход к несуществующему XML недоступны.
У регистра бухгалтерии субконто определяются назначенным планом счетов и планом
видов характеристик; их изменения обновляют дерево. Нужен backend с API 1.54.
Для регистратора и бизнес-процессов задачи тип может быть показан семейством
«Любой документ» / «Любой бизнес-процесс» без перечисления обратных связей.

Нажатие на подписку на событие открывает общий модуль в том же проекте и выделяет
имя процедуры из свойства «Обработчик». Если ссылка или процедура отсутствует,
расширение сообщает об этом. Команда **Открыть XML** открывает описание подписки.

Выбор узла модуля открывает BSL. Клик по объекту с группой **Модули** открывает
свойства независимо от количества BSL-файлов. Корень и вложенные элементы без
кода тоже открывают свойства. Команда **Открыть XML** в контекстном меню открывает
описание с выделением свойства «Имя». Файл и координаты XML предоставляет backend.
До открытия BSL его содержимое для дерева не читается. Несохранённый XML не перезаписывается:
для точного перехода требуется сохранить правки и обновить ветку.

У объекта метаданных откройте контекстное меню правой кнопкой и выберите
**Свойства**. Откроется отдельная вкладка со свойствами в стиле настроек VS Code.
В заголовке показан синоним объекта, а если его нет — имя.
Поиск работает по именам, значениям и вложенным полям; составные значения можно
раскрыть. Подписи свойств и вложенных полей берутся из каталога backend
для платформы 8.3.27/8.5.1 на языке дерева (русский или английский).
Смена языка обновляет открытую вкладку. Имя из XML доступно
для поиска вместе с подписью. Неизвестные поля и ответы старого backend
показывают исходные XML-имена.
Если у локализованного значения один язык, его текст показан без кода языка;
при нескольких языках каждая строка сохраняет свой код.
Ссылки на объекты показывают синоним (либо имя), иконку и вид метаданных.
Нажатие открывает отдельную вкладку свойств связанного объекта в том же проекте.
Если объект отсутствует или его XML не читается, рядом показана причина.
Поддержаны ссылки на стиль, язык, дополнительные формы, признаки учета,
хранилища, функциональные опции, картинки, реквизиты, значения перечислений и
предопределённые элементы. У вложенных объектов показан владелец.
Ссылка на стандартный реквизит внутри значения свойства открывает свойства
владельца; отдельный узел в группе «Стандартные реквизиты» открывает свойства самого
реквизита. Ссылка на процедуру открывает свойства общего модуля. Назначение перехода
указано в подписи.
Описание типа выводится компактным списком с ограничениями каждого типа.
Определяемые типы и характеристики доступны по ссылке, семейства вроде
«Любой документ» показаны без ссылки на отдельный объект.
`xsi:nil` показан как «Не задано»; пустая строка, Undefined и Null различаются.
Поддерживаемый backend предоставляет эти возможности через IDE API 1.9.

Технические подписи, атрибуты и пространства имён скрыты из представления;
исходник доступен через **Открыть XML**. Поиск находит читаемые подписи, синонимы
и исходные технические значения. Неизвестные структуры сохраняют свои поля.

Известные backend булевы свойства, в том числе вложенные, показаны как
флажки слева от имени. Для изменения сначала разблокируйте вкладку замочком. Пользовательская строка
`true` или `false` остаётся текстом; со старым backend без признака типа
также используется текстовое представление.
Кнопка **Открыть XML** у свойства открывает владеющий исходник и выделяет
его элемент. Повторный вызов возвращает вкладку того же объекта, а другой объект
открывается в своей вкладке. Кнопка **Обновить** перечитывает свойства из backend.
Вкладка изначально открывается для чтения. Замочек разрешает редактирование
поддержанных схемой полей только в этой вкладке. Текст сохраняется при выходе
из поля или Enter, Esc отменяет ввод; списки и флажки сохраняются сразу.
Сохранённые правки отменяются кнопками истории и Ctrl+Z/Ctrl+Shift+Z (Cmd на macOS).
Внешние изменения блокируют запись и сохраняют черновик до явного перечитывания.
Состав списков, языков и типов не меняется; доступны изменения существующих элементов.

Кнопка «Переименовать» у свойства «Имя» открывает ввод нового имени и отдельную
вкладку просмотра подтверждённых замен, перемещений и сомнительных вхождений.
Переход к исходнику позволяет проверить контекст. Сомнительные места не меняются,
а применение требует явного подтверждения их просмотра. Переименование и обычные
правки входят в общую историю объекта. Несохранённые документы проекта блокируют
переименование, его отмену и повтор. Запись и проверка ссылок выполняются backend
без зависимости от BSL Analyzer.

У **общих картинок** справа отображается превью с фоном прозрачности, форматом
и размерами. Поддерживаются отдельные PNG, JPEG, GIF, BMP, ICO, WebP, SVG и
наборы ZIP: backend выбирает наиболее детальный вариант современного интерфейса.
«Обновить» перечитывает изображение. На узкой вкладке поиск занимает строку
под заголовком и превью. При отсутствии файла или ошибке показано пояснение,
сами свойства остаются доступны. Требуется backend с capability `picturePreview`
(IDE API 1.4); более ранние backend показывают обычные свойства.
Лимит изображения — 8 MiB, архива — 32 MiB; ZIP читается без распаковки на диск.

У виртуальных групп, модулей и файлов рабочего каталога этого действия нет.

Изменения файлов передаются backend пакетами с интервалом 100 мс; изменяются
только затронутые ветви, сохраняются выделение и раскрытие соседних объектов.
Повреждённый XML показывает локальную ошибку; после исправления ветка доступна
снова. Команда **Обновить метаданные** обновляет все проекты, действие у узла —
его ветку. Ручное обновление также восстанавливает дерево после пропущенных
системой событий или исключения исходников из наблюдения настройками VS Code.
Изменения manifest автоматически переподключают контекст и могут сбросить текущее выделение.

Для дерева используются нативные элементы: клавиатурная навигация,
масштаб и темы обслуживаются VS Code. Виды метаданных, группы и роли
модулей используют локальные SVG согласованного стиля; служебные действия и
ошибки — нативные ThemeIcon. Есть цветные и контрастные варианты для светлой и
тёмной темы. Смена темы перерисовывает иконки без переподключения или сброса кеша.
Прорези прозрачны, поэтому выбранная строка не получает фоновых заплаток.

Тип объекта передаёт backend в поле `Node.metadataKind` (дополнение IDE API 1.0).
Для полного набора значков объектов нужен обновлённый backend с этим полем;
при его отсутствии или неизвестном типе показывается универсальный значок.
Группы и роли определяются по уже существующим типизированным полям протокола.
[Таблица соответствий и происхождение SVG](icons.md).

Язык названий групп и ролей модулей задаётся в **Eska › Explorer: Tree Language**
(`eska.explorer.treeLanguage`): **Авто / Русский / English** (`auto`, `ru-RU`,
`en-US`). По умолчанию «Авто» следует языку VS Code: русский для русской IDE,
английский для остальных языков. Изменение применяется сразу, без перезапуска
backend и повторного чтения метаданных; выделение и раскрытие сохраняются.
Имена объектов из конфигурации не переводятся, язык команд и ошибок остаётся
языком IDE.

## Поиск

Кнопка с лупой и команда **ESKA Explorer: Поиск метаданных** (`Search metadata`)
открывают стандартный Quick Pick. Введите часть имени или синонима объекта либо
вложенного элемента; стрелки выбирают результат, Enter раскрывает его путь и
выделяет узел в дереве, Escape закрывает поиск. Выдача содержит имя, локализованный
вид метаданных, проект и путь владельца из backend. Вид метаданных следует
настройке `eska.explorer.treeLanguage`: например,
«Общий модуль» / «Common module». Переключение обновляет открытую выдачу без
повторного поиска. Идентификаторы пути клиент не разбирает; одинаковые имена
и ID разных проектов не объединяются.

Поиск охватывает нераскрытые ветки и синонимы всех языков. Он нечувствителен к
регистру, ищет буквальную подстроку, без нечёткого сопоставления и объединения
«ё» с «е». Виртуальные группы и модули не входят в выдачу. Состав совпадений
определяет backend; стандартный Quick Pick может дополнительно сортировать
видимые строки по введённому тексту.

При первом открытии поиска eska начинает фоновую индексацию. До её завершения
показываются частичные совпадения и счётчики; ошибки отдельных XML отмечают индекс
как неполный. Сообщение «Совпадений нет» появляется только для готового индекса.
Готовый индекс повторно используется, после изменения исходников обновляется.
На каждый проект выводится не более 50 совпадений; при усечении нужно уточнить
запрос. Ввод объединяется с задержкой 250 мс, обновления прогресса — 500 мс.

Предыдущий запрос отменяется через IDE-протокол; поздний ответ не заменяет новую
выдачу. При выборе backend заново проверяет существование объекта и возвращает
путь: загружаются только необходимые ветви. Удалённый результат показывает ошибку.
Кнопка обновления повторяет поиск. Закрытие окна отменяет запросы, но уже начатый
индекс достраивается в фоне; отключение проекта закрывает поиск и backend.

## Подсветка изменений Git

Дерево использует статусы встроенного Git-расширения VS Code и цвета текущей темы:
`M` — изменённый исходник, `A` / `U` — добавленный или неотслеживаемый,
`R` — переименование, `D` — удаление, `!` — конфликт.
Объекты и группы с изменениями внутри отмечаются точкой `•`.
Удалённые элементы, которых уже нет в метаданных, отдельно в дерево не добавляются.

Подсветка обновляется по событиям Git и метаданных, включая добавление в индекс
и коммит. Это статус файлов, а не сравнение отдельных свойств XML; несохранённый
текст сам по себе Git-статус не меняет. Для исходников форм код и XML отмечаются
раздельно. Источник статуса выбирает настройка `eska.explorer.scm.mode`.
Настройка `git.decorations.enabled` отключает её вместе с Git-декорациями редактора.
Расширение не запускает дополнительный опрос Git и не индексирует всю конфигурацию:
пути проверяются при запросе декораций отображаемых ветвей.

## Изменения в обозначениях 1С

В стандартной панели **Система управления версиями** доступно представление
**ESKA: изменения 1С**. Например, изменение `ObjectModule.bsl` отображается как
`Документ.ВыдачаЗайма.МодульОбъекта`. Физический путь остаётся в описании и подсказке.
Для остальных файлов сохраняется обычное имя. Переименование показывает старое
и новое обозначения. Файлы одного объекта можно индексировать по отдельности.

Счётчик группы включает все найденные файлы. В группе до 200 файлов строки
отсортированы по обозначению. В более крупной группе они идут по пути. Панель
загружает обозначения по мере прокрутки. Нажатие `End` на строке переносит
фокус в конец списка, `Home` — в начало. Если список обновился во время
выделения большого диапазона с `Shift`, выделите диапазон заново.

В настройках VS Code найдите `eska.explorer.scm.mode`. Для каждой папки с
`eska.toml` в корне можно выбрать один из трёх режимов.

| Значение | Поведение |
| --- | --- |
| `eska` (по умолчанию) | После первого снимка ESKA берёт репозиторий под наблюдение и закрывает его в штатной панели Git. Список изменений и подсветка в дереве получают статус из одного монитора ESKA даже при скрытой панели. |
| `vscode` | Для папки работает штатная панель Git с её наблюдением, индексированием и коммитами. |
| `both` | Доступны обе панели. Штатный Git обновляет своё представление, а открытая панель ESKA получает снимки через `eska-vcs monitor`. |

В режиме `eska` строка состояния показывает ветку выбранного репозитория.
Нажмите на имя, чтобы переключиться на другую локальную ветку. При отсоединённом
HEAD отображается короткий хеш коммита. В режимах `vscode` и `both` этот
элемент предоставляет штатный Git.

Режим применяется сразу. У папок без `eska.toml` остаётся штатный Git.
Если несколько открытых папок делят один Git-репозиторий и хотя бы одной из них
нужен штатный Git, он остаётся открытым для этого репозитория. При переходе на
`vscode` или удалении манифеста Explorer возвращает штатному Git репозиторий,
который ранее закрыл. Если установленный `eska-vcs` не поддерживает автономный
режим, Explorer сохраняет доступный штатный Git. Для индексирования и записи
в репозиторий компонент использует системный Git. Настройки встроенного Git,
включая `git.autorefresh`, сохраняют свои значения.

В доверенной рабочей области Explorer передаёт пути из общего потока файловых
событий VS Code команде `eska-vcs monitor --events-stdin`. ESKA вычисляет
статус по этим путям через gix. Сохранение в редакторе обновляет список даже для
файлов под `files.watcherExclude`. Полная сверка каждые 30 секунд подхватывает
пропущенные внешние правки. При включённом штатном Git в режиме `both` закрытие
панели ESKA освобождает её монитор.

Контекстное меню и кнопки
рядом с файлами и группами соответствуют штатному представлению Git. Например,
из строки можно открыть файл, посмотреть изменения или версию из HEAD,
индексировать изменения либо отменить индексирование. Поддерживается выбор
нескольких файлов. Если файл изменён и в индексе, и в рабочей копии, он
отображается дважды. Сравнение в группе индексированных изменений открывает
HEAD и индекс, а в группе рабочих изменений — индекс и текущий файл.

У каждого репозитория своё поле сообщения. В режиме `both` оно общее со штатным Git.
Чтобы создать коммит, введите сообщение и нажмите **Фиксация** или
`Ctrl+Enter` (`Cmd+Enter` на macOS) в поле сообщения. Панель вызывает `eska save`
для подключённого проекта. Когда репозиторий содержит несколько доступных
проектов, панель предлагает выбрать область. Для workspace, открытого из корня
его репозитория, можно сохранить изменения workspace одним коммитом.
`eska save` включает подготовленные и неподготовленные изменения выбранной области.
При несохранённых буферах сначала сохраните изменения в редакторе. При установке
только VCS-компонента панель вызывает `eska-vcs save`. В автономном режиме
версии HEAD и индекса для сравнения предоставляет `eska-vcs`.

Отмена изменений требует подтверждения. Она отклоняется при несохранённых
правках в затронутых файлах и при изменении файлов или HEAD после открытия
диалога. Добавление в GITIGNORE записывает правило для выбранного пути
в корневой `.gitignore`. Сначала сохраните несохранённые правки этого файла.
Если проект, репозиторий или список изменений обновился и действие устарело,
выберите строки заново.

Обозначения формирует `eska-project` с Metadata API 1.54 или новее, используя ту
же модель, что и `eska diff`. Запрашиваются только изменённые пути. Со старым
компонентом список показывает имена файлов.

[![Сравнить изменения модулей по именам объектов — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11-18/explorer-scm.gif)](https://odineska.tech/eska/docs/#demo-scm)

## Диагностика подключения

Команда **ESKA Explorer: Показать журнал подключения** открывает журнал VS Code.
В нём записываются время, PID, путь к backend, его версия и параметры проекта;
для каждого запроса — ID, метод, поколение, размер очереди и время выполнения.
Ошибки содержат категорию backend, причину и адрес исходника, если они известны.
Текст XML/BSL и полные тела запросов/ответов в диагностические события не попадают.
Пакеты событий файлов содержат количество путей и ограниченный образец.

`request_timeout` показывает, какой запрос не завершился, сколько он ожидал,
когда последний раз приходили данные и получен ли неполный ответ. Если после
него стоит `process_signal` с причиной `timeout`, процесс завершило расширение.
`process_closed` показывает код выхода, сигнал и инициатора остановки. Обычное
отключение не записывается как авария.

Сообщения stderr сохраняются в пределах первых 16 КБ и последних 16 КБ:
при превышении лимита поздняя причина завершения остаётся в `stderr_tail`.
Для разбора сбоя нужны события от `connection_connect` до `process_closed`.
Тайм-ауты не увеличены: журнал помогает отличить медленную операцию/очередь от
аварийного выхода, но сам по себе не устраняет причину задержки.

## Где работает backend

Минимальная версия VS Code API — **1.109.0**. Расширение объявлено как `workspace`:
в Remote SSH, WSL и Dev Containers требуется настроить project backend на соответствующей
машине/в контейнере. Настройка пути допускает отдельные значения для этих сред.
Виртуальные workspace и web extension host без Node не поддерживаются;
в недоверенной рабочей области расширение отключено.

UI лишь отображает результаты backend: парсер XML, каталог типов и кеш остаются
в eska. При открытии включён дисковый кеш backend. Источник никогда не сканируется
вторым индексатором на TypeScript.

## Активность подпроектов

С Metadata API 1.35 (`workspaceActivity`) у корней подпроектов есть
действия включения/отключения, а в заголовке дерева — фильтр отображения
отключённых. У этих действий разный смысл:

| Действие | Результат |
| --- | --- |
| Отключить подпроект | Освободить его индексы и наблюдатели, отменить относящиеся к нему фоновые работы |
| Скрыть отключённые | Скрыть корни без изменения активности |
| Включить подпроект | Вернуть доступность контекста с ленивой загрузкой |
| Показать отключённые | Вернуть отключённые корни в дерево без включения |

Состояние активности сохраняется локально и не записывается в переносимый
`eska.toml`. Это не фильтр состава сборки или CI: явный CLI по-прежнему выбирает
проекты из manifest. Открытие обычного файла, поиск и переход от файла не включают
проект скрыто. Выключенный корень при показе остаётся узнаваемым, но его metadata-
операции недоступны; старые ответы и вкладки не выдают новое разрешение записи.

Backend проверяет `requiredBy` по **всем активным приложениям**, а не только
выбранному языковому контексту. Отключение нужной им базы или расширения
освобождает metadata-ресурсы, но сохраняет необходимые семантические исходники;
подсказка перечислит потребителей. `depends_on` и роли берутся из manifest;
reference-библиотека не превращается в отдельный writable подпроект.

В окне остаётся один выбранный языковой контекст. Отключение отдельного
потребителя не перезапускает общий Analyzer, пока в контексте есть другой
активный потребитель. Последний потребитель освобождает lease и останавливает
сервис. Повторное включение выполняет нормальную проверку config/lease; устаревшие
снимки отклоняются. Старый backend без capability не получает клиентскую имитацию.

Два и более видимых расширения, отчёта или обработки одного типа образуют
виртуальную группу. Фильтр может менять число видимых корней и вид группы,
но не изменяет исходники или manifest. Конфигурации и одиночные подпроекты
остаются на исходном уровне. Сортировка, раскрытие и поиск учитывают эти группы.

## Настроить проект

В контекстном меню группы **Настройки проекта** откройте **Настроить проект**.
Форма использует тему редактора и показывает разделы проекта и сборки,
форматирования, анализа BSL, проверок, Git, запуска и отладки. Общий
`eska.toml` рабочего пространства доступен из его собственной файловой группы.

Для форматтера выберите базовый пресет и задайте переопределения флажками,
списками или числовыми полями. **Наследовать** снимает переопределение.
Командные профили и правила для отдельных путей находятся в расширенных
настройках форматирования. **Анализ BSL** показывает параметры по группам.
Поиск вверху фильтрует настройки и диагностические правила по названию или коду.

**Предпросмотр** сравнивает текущее и предложенное содержимое файла.
**Сохранить** проверяет изменения и записывает правки в выбранный файл.
Для политики анализатора установленный BSL Analyzer проверяет производный
конфиг до записи. После сохранения Explorer показывает статус его обновления.
Git LFS настраивает шаблоны в `.gitattributes` для последующего добавления
файлов в Git. В **Запуске и отладке** отдельные наборы флажков управляют
автоподключением `test` и `prod`. Пустой собственный набор отключает его.

Для общих настроек нужен `eska-project` с командой `settings-project`.
Описание файлов и исключений приведено в
[руководстве ESKA](https://github.com/odineska/eska/blob/main/docs/user-guide.md#configuration).

## Файлы рабочей области

Корни конфигураций и общие файловые группы — непосредственные дети представления
ESKA. Промежуточного узла рабочей области нет. Разделы метаданных находятся
прямо внутри конфигурации, без группы «Структура проекта 1С».

У участников workspace после разделов метаданных показаны собственные файловые
группы. У самостоятельного проекта с единственным корневым `eska.toml` файловые
группы находятся на общем уровне, рядом с конфигурацией. Открытие отдельного
участника workspace не добавляет файлы родительской папки.

Классификация одинакова на обоих уровнях и применяется к непосредственным
детям соответствующего каталога:

| Группа | Содержимое |
| --- | --- |
| Настройки проекта | Файлы и каталоги из списка ниже |
| Документация | `README.md`, `README.<язык>.md`, `README-<язык>.md`, без учёта регистра |
| Прочие файлы | Остальное, включая `build`, `.git/`, `.eska/` и неизвестные скрытые папки |

В настройки входят следующие имена (с учётом регистра):

| Назначение | Файлы и каталоги |
| --- | --- |
| ESKA и BSL | `eska.toml`, `bsl-analyzer.toml`, `.bsl-language-server.json` |
| Git | `.gitignore`, `.gitattributes`, `.gitmodules`, `.lfsconfig`, `.mailmap` |
| Агенты | `.codex/`, `.agents/`, `AGENTS.md`, `AGENTS.override.md`, `.claude/`, `CLAUDE.md`, `.cursor/`, `.cursorrules` |
| Редактор | `.vscode/`, `*.code-workspace`, `.editorconfig` |
| Платформы репозитория | `.github/`, `.gitlab/`, `.gitlab-ci.yml`, `.gitea/`, `.forgejo/` |

Каталоги из списка показываются целиком, без переноса их вложенных файлов
в другие группы. Произвольные Markdown-файлы и скрытые файлы автоматически
настройками не считаются. Глобальные настройки вне проекта не добавляются.

Папки исходников и корни участников исключены из обычного файлового дерева.
Вложенные папки сохраняют физическую структуру; README внутри такой папки
остаётся на своём месте. Если участники лежат внутри `src`, его прочие файлы
доступны через `Прочие файлы → src`; сами участники там повторно не выводятся.
Папки-контейнеры участников (например, `src`) скрываются, если после исключения
проектов в них ничего не остаётся. Проверяются только каталоги на пути к
участникам, без обхода их исходников. При добавлении прочих файлов папка
снова появляется. При `project.source = "."` отдельной папки
исходников нет; неклассифицированные XML также доступны в файловой ветви.

Пустые файловые группы скрываются независимо от фильтра метаданных. Имена
файлов сохраняются, подписи групп следуют настройке языка дерева. Выбор файла
открывает его стандартным редактором VS Code. Иконки и Git-подсветка физических
файлов используются из редактора.

Каждая папка читается асинхронно только при обращении к ней. Снимок её
содержимого переиспользуется до файлового события или команды обновления.
Наблюдатели нерекурсивные; скрытые и игнорируемые Git файлы видны. Настройки
исключений наблюдения VS Code могут задержать автоматическое обновление —
в этом случае используйте кнопку обновления дерева или папки.
Символические ссылки видны, ссылки на папки раскрываются; переход назад
к физическому предку останавливает ветвь, предотвращая цикл.

Поиск по лупе по-прежнему ищет метаданные, а не имена произвольных файлов.
Команда перехода от открытого файла поддерживает обе части дерева.
Основа UI — [Tree View API](https://code.visualstudio.com/api/extension-guides/tree-view).


## Порядок объектов

Кнопка сортировки на строке проекта включает или выключает алфавитный порядок
одним нажатием. Заполненная светлая иконка в тёмной теме (тёмная в светлой)
означает, что сортировка включена. Повторное нажатие возвращает исходный порядок.
По умолчанию сортировка выключена; выбор сохраняется отдельно для каждого проекта.

Сортируется всё дерево метаданных: корневые группы, содержимое «Общие», объекты,
подчинённые группы, роли модулей и все вложенные элементы. Сравнение следует языку
дерева, не различает регистр и учитывает числа: `Поле2` раньше `Поле10`.
При равенстве имён сохраняется исходный порядок. Порядок самих проектов и физических
файлов не меняется. XML, ленивая загрузка и поисковый индекс остаются прежними.
