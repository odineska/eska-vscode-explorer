# Пакетная приёмка форм

`test/form-batch.mjs` собирает один VSIX и последовательно запускает выбранные
серии через существующий `test/run-host.mjs`. Каждая серия получает отдельный
профиль, установку расширения и свободный CDP-порт. Окна не используют общий
Extension Host. Проверки закрытия, повторного запуска и восстановления сохраняют
свои исходные границы. Одновременно запускается одна GUI-серия. В приватном профиле отключены
телеметрия и фоновые обновления; CLI получает штатный `--disable-telemetry`.
Его код выхода и timeout продолжают определять результат установки.

Каталог `test/form-suites.json` содержит имена драйверов и пути их эталонов.
Наборы `buttons`, `appearance`, `sessions` задают очередь. Можно повторить
`--suite <id>`, чтобы выбрать собственную очередь. Выбор применяется к целым
сериям: фильтрации отдельных cases нет, переходы dirty/floating/reattached
и связанные контрольные примеры выполняются самим драйвером полностью.

```sh
node test/form-batch.mjs --list
node test/form-batch.mjs --help
node test/form-batch.mjs \
  --eska-root ../eska \
  --backend ../eska/target/debug/eska-project \
  --code /path/to/vscode-executable \
  --cli-js /path/to/resources/app/out/cli.js \
  --ru-language-pack /path/to/unpacked-language-pack/extension \
  --preset buttons --locales en,ru
```

Пути к VS Code, CLI и распакованному language pack должны быть абсолютными.
`--code` может указывать на используемый стендом wrapper; его хэш относится
именно к wrapper, а не к executable, который тот вызывает. Для Windows укажите
настоящий `Code.exe` и `.exe` backend; запуск из PowerShell использует те же
параметры. Переносимость runner не означает выполненную Windows-приёмку.
`--locales en` не требует русского language pack. `--build-tool` позволяет
выбрать executable Bun. По умолчанию выполняются `bun run check`,
`bun run compile`, затем упаковка штатным VSCE через Node.

Playground всегда вычисляется как `<eska-root>/../eska-playground`; он должен
существовать. Runner создаёт только собственный уникальный `form-batch-*`.
Содержимое каталога сохраняется для разбора. Backend нужно собрать заранее:
runner фиксирует фактический файл и явно записывает `rustBuildPerformed:false`.
Для серии `application` дополнительно нужны `--application-project` и
`--application-samples` с существующим workspace и JSON-списком форм. Этот
внешний workspace не копируется runner и не считается замороженным эталоном.

## Результаты и входы

- `batch.json`: результаты, коды выхода, сигналы, длительность, классификация,
  пути логов и receipt, фактические запуски host и регистрации локали.
- `inputs.json`: commits и исходное dirty-состояние обоих репозиториев, хэши
  исходников/драйверов, backend, VSIX, каждого runtime-ресурса, всех эталонов,
  environment и скопированного language pack.
- `artifacts/`: использованные VSIX, копия backend и language pack.
- `fixtures/`: копия всего каталога эталонов, сохраняющая соседние относительные
  ссылки между наборами. Каждый пакетный запуск использует собственную копию.
- `<suite>-<locale>/`: stdout/stderr драйвера, host log, receipt и результаты,
  которые сохраняет конкретный драйвер; `check.log`, `compile.log`,
  `package.log` фиксируют подготовку.

Число `hostStarts` учитывает запуски launcher в `run-host.mjs`; отдельные
вспомогательные окна подтверждаются флагами конкретного драйвера.

Receipt содержит время CLI-установки и проверки runtime, подготовки, тела
серии, native-host и очистки. Тело серии включает её подключение, assertions
и teardown; это не отдельный замер чистого CPU-времени assertions.
`caseIds` перечисляет случаи, опубликованные драйвером в `results` или `cases`;
для агрегатного отчёта используется `<suite>/suite`. Это не перечень всех
внутренних assertions. Повторные запуски восстановления сохраняются отдельно.
Регистрация локали имеет фазу `language-registration`; её ограниченные повторы
проверяют готовность IDE. Пиксельные расхождения повторным запуском не скрываются.

Перед GUI-запусками проверяются байты VSIX и checkout, а после установки —
все упакованные файлы `out/**` и `resources/**` в установленном расширении:
JS, CSS, шрифты, WASM, картинки и прочие runtime-ресурсы. Несовпадение или
отсутствующий ресурс прерывает серию как `harness`. Проверка охватывает содержимое
архива, а не только `extension.js`. Для форм обязательно наличие renderer
JS/CSS, шрифта и WASM. До и после каждой серии проверяются изменения набора
исходников/драйверов; изменение скопированных эталонов также инвалидирует запуск.

Ошибка одной серии даёт общий ненулевой exit code; следующие независимые
серии продолжаются. Изменение входов останавливает очередь. Известные ошибки
проверки артефактов классифицируются как `harness`; ошибки старых драйверов
могут остаться `unclassified` и требуют разбора лога. Нулевая терпимость к
пикселям и правила native-эталонов определяются существующими драйверами;
пакетный runner их не ослабляет.
