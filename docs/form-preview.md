# Просмотр управляемых форм (beta)

Просмотр доступен для функционального тестирования на Linux и Windows.
[Приёмка Windows ru/en](windows-forms-acceptance-2026-11-07.md) включает установленный
VSIX, отдельные окна и 97 форм после roundtrip платформы. Команда и строка
состояния помечены как beta. Возможны небольшие различия геометрии, сглаживания
и пользовательских цветов; полная матрица свойств и сочетаний ещё не принята.
Визуальная приёмка Windows, другие DPI и интерфейс 8.5 остаются открытыми.
Это статический просмотр Designer XML: BSL и команды формы не исполняются,
исходники просмотрщиком не записываются. Графическое редактирование не входит
в beta. Выбор, страницы и группы, свойства, XML-навигация, живое обновление
и отдельное окно доступны в проверенных сценариях.

Узел управляемой формы открывает просмотр на SolidJS. Команда
**Открыть просмотр формы (beta)** доступна также для `Form.xml`; **Открыть XML формы**
открывает обычный исходник. Нужен `eska-project` с capability `formPreview`
Metadata API 1.40 с `formPreview.pictures:true` и `formPreview.inputPreparation:true`.
Старый backend продолжает обслуживать остальные согласованные возможности.

Инспектор использует активную тему VS Code, включая высококонтрастные темы.
В широкой вкладке доступны панели **Структура**, **Данные** и **Свойства**.
В узкой встроенной вкладке переключатель **Элементы / Данные** освобождает место
для просмотра. После открепления изображения три панели остаются в одном ряду
и занимают всю высоту. Если окно становится слишком узким для трёх читаемых
колонок, инспектор прокручивается горизонтально. Размеры меняются мышью или
клавишами на разделителе. Рабочая область запоминает размеры,
вкладки, раскрытые узлы, поиск и выбор для последних 40 форм с учётом приложения.

Общий поиск учитывает техническое имя, заголовок, путь к данным и тип реквизита.
В дереве сохраняется исходный порядок, а результаты поиска показываются вместе
с родительскими узлами. Стрелки, Home и End перемещают выбор. F12 открывает
исходник выбранной строки, если её источник известен.

Выбор элемента обновляет свойства и выделяет соответствующий реквизит по полному
пути. В свойствах реквизита перечислены все использующие его элементы, в свойствах
команды доступны действие и связанные кнопки. Клик по изображению синхронизирует
выбор. Действие **Показать на форме** открывает нужную страницу, раскрывает группы
и прокручивает к элементу в том окне, где сейчас отображается форма.
**Перейти к XML** открывает проверенный исходный диапазон.

Тип показывается кратко в списке. В полном описании каждый вариант составного
типа занимает отдельный блок. Длина, точность, знак и состав даты подписаны
на языке интерфейса. Исходное техническое описание раскрывается отдельно и
копируется целиком. Metadata API 1.45
добавляет поля основного реквизита и табличных частей, включая поля, которые
форма напрямую не использует. Для старого API доступны объявления в форме
и пути из известных привязок элементов.

При Metadata API 1.41 и `formPreview.propertyPalette:true` обычная
вертикальная группа показывает проверенные категории палитры Конфигуратора.
Незаписанные настройки отображаются как значения платформы. Переход
доступен для записанных полей, включая повторяющиеся поля и записи из
расширений. Для остальных элементов и backend 1.40 записанные в XML
свойства распределяются по контекстным группам. Исходные имена неизвестных
свойств доступны в группе **Дополнительно**.

Для 49 общих свойств формы backend возвращает подписи ru/en. Неизвестные
свойства сохраняют XML-имя; исходный QName доступен в подсказке строки.
Логические значения с подтверждённым типом показываются недоступными флажками,
строковые значения `true`/`false` остаются текстом. Составные значения и их
атрибуты раскрываются по запросу, включая повторяющиеся записи событий и
ограничения типов реквизитов. Раскрытые записи сохраняются при dirty-обновлении.
Enter/F12 на строке свойства открывает её исходный диапазон. Навигация учитывает
нормализацию окончаний строк редактором после проверки хеша исходных байтов.
Единственный языковой вариант локализованного свойства показывается обычным
текстом, даже если его язык отличается от языка интерфейса. Несколько вариантов
раскрываются по языкам. Пустое содержимое и дополнительные атрибуты сохраняются;
нестандартные вложенные поля доступны в исходной составной структуре.
[Проверка локализаций Linux ru/en](measurements/t161-localized-values-linux.json).
Полный каталог применимых свойств и значений по умолчанию ещё требует реализации.

Metadata API 1.39 с `formPreview.handlerNavigation:true` добавляет переходы
из событий выбранного элемента и действий команд к существующим обработчикам.
ESKA выбирает модуль по происхождению свойства и ищет объявление в текущем
тексте документа, включая несохранённый BSL. Анализатор для этого не нужен.
Модули не создаются и не сохраняются. Отсутствующее или неоднозначное
объявление показывает сообщение в просмотре и сохраняет готовую модель формы.
Квалифицированные вызовы общих модулей, выбор ветвей препроцессора и цепочки
переопределений BSL расширения пока не разрешаются.

**Открепить** переносит предпросмотр в отдельное штатное окно VS Code.
Его можно разместить на другом рабочем столе. Дерево и изображение разделяют
сессию и выделение. **Вернуть** возвращает изображение в основную вкладку.
Пока изображение откреплено, дерево, реквизиты и свойства занимают всю
освободившуюся высоту. Кнопка **Показать окно просмотра** остаётся на панели
инструментов. Возврат или закрытие отдельного окна восстанавливает сохранённое
разделение; в маленьком окне оно ограничивается доступной областью.
[Проверка Linux ru/en](measurements/t163-detached-space-linux.json).

Изображение адаптируется к доступной области основной вкладки или отдельного
окна. Перемещение разделителей также меняет компоновку. Вложенные группы,
страницы, растягиваемые поля, таблицы и сложные поверхности получают выделенное
место; фиксированные элементы сохраняют размеры. Если содержимое не помещается,
появляется прокрутка. Широкие колонки таблицы прокручиваются внутри таблицы.
На Linux при прокрутке тела внутри рамки главная панель команд остаётся
на исходном месте. Проверены основная вкладка и отдельное окно, resize,
доступность кнопок для нажатия, сохранение выбора и DOM без записи XML.
Масштаб текста задаётся выбранным zoom и сам при изменении окна не меняется.

Размеры окна и области просмотра остаются локальными: они не записываются
в XML и не меняют геометрию другого окна. Сохраняются выделение, выбранная
страница и раскрытие групп; resize не создаёт новую сессию и не отправляет
запрос разбора формы. На Linux проверены несколько размеров, zoom 125%,
несохранённый XML и Undo/Redo. Эта функциональная проверка не подтверждает
полное совпадение с Конфигуратором при любых размерах и DPI; Windows и полная
матрица динамических ограничений требуют отдельной приёмки.
[Linux-матрица и результаты проверок](measurements/t157-responsive-layout-linux.json).

Если две объединённые вертикальные группы стоят рядом и их предпочитаемые
ширины превышают доступное место, в промежутке появляется пунктирный
разделитель. Перетащите его мышью или выделите клавишей Tab и используйте
стрелки влево и вправо. Home и End переводят границу в допустимые крайние
положения. Ширины ограничены минимальными размерами содержимого. Когда
колонки помещаются, возвращается автоматическая раскладка. Положение
разделителя хранится локально в окне предпросмотра.

Закрытие последнего потребителя освобождает backend-сессию. После reload
восстанавливается привязка к форме и UI, затем заново запрашивается модель.

Подписи обычных доступных текстовых кнопок Linux рисуются комплектным
FreeType 2.13.2 и Liberation Sans 2.1.5, включая обычное и жирное начертание.
Учитываются кернинг, кириллица, диакритика и явный цвет текста из XML.
Это ПО использует FreeType Project (https://freetype.org); лицензии входят в VSIX.
Нативные библиотеки устанавливать не требуется. Неподдержанное написание,
другая гарнитура или ошибка ресурса оставляют доступный браузерный текст
и сообщение о неполном визуальном совпадении. Основные, плоские, недоступные
кнопки и кнопки с картинкой пока используют прежнее отображение.
Совпадение внутренних областей 66 кнопок проверено отдельно; полная пиксельная
приёмка рамок, заголовков и остальных элементов формы продолжается.

Боковые подписи доступных полей ввода Linux используют цветное LCD-сглаживание
того же FreeType. Прежняя DOM-компоновка сохраняет размеры и координаты полей.
Для `Name:`/`Amount:` проверены полные прямоугольники, включая сглаживание;
остальные состояния и варианты оформления требуют полной визуальной приёмки.

Заголовки страниц учитывают `TitleFont`/`TitleTextColor` группы страниц и
переопределения отдельной страницы. На Linux верхние вкладки используют тот же
LCD-растеризатор. Размеры заголовков откалиброваны для Liberation Sans при
8, 10, 12, 14, 16, 18, 20, 24, 28, 32 pt; остальные размеры сохраняют
приближённую геометрию и браузерный текст с сообщением о неполном совпадении.
Шрифт содержимого страницы не меняется вместе со шрифтом вкладки.

Подпись окна формы Linux использует комплектный LCD-растеризатор и отдельные
метрики заголовка: Liberation Sans Bold 11 px. Проверены латиница, кириллица,
«Ё», знак номера, межбуквенные пары и обрезание длинной подписи. Изменение
заголовка в несохранённом XML обновляет текст в существующем DOM.

Кнопка выбора числового поля Linux использует native-ширину 20 px и общий
значок калькулятора 9×11 px. Разделитель следует цвету рамки поля; кнопка
сохраняет белый фон при изменении цвета самого поля. Правая граница рисуется
на 1 px дальше логического размера кнопки, сохраняя layout. Скругления рамки
и все недоступные состояния ещё требуют пиксельной приёмки.

Статическое значение числового поля Linux отображается комплектным LCD-
растеризатором. Проверены «0» обычного/увеличенного шрифта и явный цвет текста
на цветном фоне. Исходное поле сохраняет значение и доступное имя. Другие
выравнивания, недоступные состояния и полная геометрия формы ещё проверяются.

Несохранённые изменения XML и связанных найденных метаданных, Undo/Redo,
сохранение и внешние изменения файлов обновляют изображение. При ошибке
остаётся последнее корректное изображение с отметкой устаревшего состояния.
Просмотр не записывает исходники и не выполняет BSL.

Для выбранного стиля читаются значения из `Styles/<Name>/Ext/Style.xml`,
включая переопределения пользовательских элементов цвета и шрифта. Изменения
этого файла без сохранения обновляют обе области просмотра; повреждённый XML
сохраняет последнее корректное оформление. Частичное свойство шрифта формы
применяется поверх значения элемента стиля. Автоматическое оформление Такси
не заменяется значениями старых системных ролей. Явные ссылки на пять цветов
Такси принимают выбранные значения; автоматический заголовок группы использует
AccentColor. Изменение выбора стиля в XML конфигурации также обновляет форму.
Пользовательские элементы цвета, включая имя `TextColor`, разрешаются по
определению и выбранному стилю; внутренние имена цветов профиля их не подменяют.
[Проверка имён цветов](measurements/t155-native-style-color-roles-linux.json)
фиксирует native-матрицу и живые обновления определения и payload.
Полная матрица потребителей палитры ещё проходит сверку с платформой.
[Результат Linux-проверки](measurements/t155-native-style-palette-linux.json)
содержит точные области сравнения и оставшиеся ограничения.

Предопределённые ссылки на шрифты отделены от пользовательских элементов
стиля. На Linux обычная кнопка с `NormalTextFont` использует 10 pt,
`SmallTextFont` и `TextFont` — 8 pt, `LargeTextFont` — 14 pt,
`ExtraLargeTextFont` — 18 pt. Пользовательский `StyleItem.TitleFont` принимает
значение выбранного стиля, fallback определения и частичные атрибуты формы.
Кнопки одной командной строки выравниваются по самой высокой; подписи и фон
перерисовываются при изменении её высоты. В ru/en приняты 78 234 пикселя
внутренних областей, включая dirty-шрифт и отдельное окно.
[Проверка шрифтов Linux](measurements/t155-native-font-roles-linux.json)
содержит эталоны и точные границы приёмки. Автоматическое оформление основной
кнопки и Windows остаются отдельной проверкой.

Модель объединяет базу и расширения выбранного приложения и разрешает
подписи, типы и ссылки на оформление. Тема оболочки следует VS Code;
область формы использует отдельный светлый профиль Такси 8.3.27. В Linux
стандартные Liberation Sans/Serif/Mono 2.1.5 включены в VSIX с лицензией OFL.

На Linux ширина подписей кнопок, вкладок и табличных команд учитывает
хинтинг комплектных шрифтов. Метрики включены в пакет; FreeType на компьютере
пользователя не требуется. Таблица рассчитана для целых размеров 1–128 px;
за её пределами, для другой гарнитуры или символов с контекстным формированием
сохраняется измерение браузером. Это ограничение точности, а не подтверждение
совпадения таких подписей с 1С. Проверены 48 кнопок Liberation Sans обычного
и полужирного начертания при 10–32 pt, включая изменение размера в dirty XML.
Геометрия и пиксели обычных подписей проверяются раздельно по native-эталонам.

У обычных доступных кнопок Linux фон и подпись рисуются совместно. Явный
`BackColor` задаёт основу градиента; изменение из dirty XML обновляет фон и
пиксели текста в основном и отдельном окнах с сохранением DOM. Проверены
18 цветов и дополнительные размеры шрифта до 32 pt. Основные кнопки, картинки,
меню, рамки и углы сохраняют отдельную пиксельную приёмку. Изменение обычной
кнопки в основную снимает обычный фон и восстанавливает его при возврате.
В Linux явный BackColor имеет приоритет и при DefaultButton=true: кнопка
получает обычную заливку и обычный автоматический цвет текста. Собственный
TextColor сохраняется; значение DefaultButton в модели остаётся исходным.
[Проверка приоритетов](measurements/t158-native-primary-overrides-linux.json)
включает RGB, ссылки на стиль и dirty-переключение флага.
[Измерения цветного фона Linux](measurements/t158-native-button-colors-linux.json)
сохраняют границы принятой области и непроверенные состояния.

## Текущие ограничения

Полное визуальное совпадение с Конфигуратором ещё не принято. Основные
контейнеры, поля, кнопки, страницы, таблицы и поверхности сложных полей
реализованы, но метрики, автокоманды, варианты ресурсов картинок и все комбинации
визуальных свойств требуют дальнейшей сверки с платформой. Пустая поверхность
сложного поля пока не означает подтверждённой поддержки его native-предпросмотра.
Описание условного оформления сохраняется в модели; runtime-значения не вычисляются.
Интерфейс 8.5 и графическое редактирование относятся к следующим задачам.

Linux: установленный VSIX проверен на VS Code 1.109.0 ARM64 в ru/en:
dirty XML, отдельное native-окно, общее выделение, ошибочный XML, Undo/Redo,
возврат, внешняя правка и навигация. Проверка показала отсутствие записи
во время просмотра и сохранение DOM формы при изменении заголовка.
Проверены также две независимые формы, закрытие основной вкладки перед возвратом
preview и восстановление ошибочного первого снимка. Reload окна и обычный
перезапуск установленного VS Code сохраняют обе панели, отдельное окно,
dirty XML, выбранную страницу и элемент, масштаб и высоту областей.
Модель и серверная сессия запрашиваются заново. Отключение/перезапуск backend
сохраняет последнее изображение и подхватывает актуальный dirty-текст;
задержанный ответ прежнего процесса не публикуется. Windows и разные DPI
требуют отдельной приёмки.

Требования и оставшиеся этапы:
[T152–T165](https://github.com/odineska/eska/blob/codex/design-xml-analyzer/docs/roadmap/30-managed-form-preview.md).


Случайные значения демонстрационных данных диаграммы не участвуют в пиксельном
сравнении: Конфигуратор меняет их при каждом открытии. Исключение согласовано
с пользователем; размеры, оси, подписи, легенда, палитра и оформление сравниваются.
Регион календаря берётся из среды Extension Host отдельно от языка оболочки.
Все 20 форм из native-bound-fields проверены установленным VSIX в ru/en по размерам контролов;
эта проверка ещё не заменяет полную пиксельную приёмку.

Уточнены вид по умолчанию индикатора, ползунка и поля картинки, образцы
переключателя и однодневного планировщика, отсутствие сетки и заголовков пустого
табличного документа. Некоторые ширины подписей ещё расходятся с native.


Общие картинки Designer XML разрешаются из состава приложения и передаются
как ограниченные инертные изображения. SVG и ZIP-варианты читаются существующим
resolver; архивы не извлекаются. Несохранённый `Ext/Picture.xml` переключает
локальный payload; сохранённая замена изображения обновляет preview. Бинарные
данные не принимаются как XML overlays. В модели остаётся диагностика отсутствующей
общей картинки. Выбор всех вариантов размера/плотности, LoadTransparent и полная
калибровка стандартных картинок ещё требуют проверки.

Для связанной стандартной команды справки используется `StdPicture.Help`.
У обычной кнопки `Auto` показывает текст, а `Picture` и `PictureAndText`
учитывают картинку. Собственный `Picture` имеет приоритет; `Ref=0` очищает
его. Явный `Picture` без заданной картинки оставляет кнопку без подписи;
недоступная ссылка сохраняет диагностику и текстовый fallback.
На Linux геометрия 13 обычных форм проверена при 10/16 pt в ru/en, включая
несохранённые изменения и отдельное окно. Полные пиксели новых сочетаний,
другие шрифты, DPI и Windows требуют отдельной сверки.

Автозаполнение главной панели учитывает тип основного реквизита, стандартные
команды справочника/документа и команды метаданных в `FormCommandBarImportant`
с подходящим типом параметра. Подписи учитывают переопределения расширений.
Эти команды видны и во вкладке командного интерфейса. Серверные команды открытия
остаются в дереве, но скрыты в обычном настольном предпросмотре. Остальные группы
команд и меню пока требуют сверки с Конфигуратором.

Меню «Ещё» динамического списка учитывает справочник, документ, журнал,
периодический регистр сведений и запрос без основной таблицы. Отображаются
стандартные секции, сочетания клавиш и вложенные меню поиска, иерархии и создания
документов журнала. Исключения команд и несохранённые изменения XML обновляют
меню в основном и отдельном окне. Для документов журнала используются синонимы,
упорядоченные по видимой подписи. Растры Linux включают отдельные варианты
значков списка и шаблонную картинку ссылки, которая наследует цвет пункта.
Минимальная ширина некоторых вложенных меню ещё расходится с эталоном.
Полная пиксельная приёмка меню и проверка Windows продолжаются.

Тип, подпись и проверка заполнения привязанных реквизитов учитывают частичные
переопределения расширений. Пустое поле ввода получает красную пунктирную отметку
по итоговой проверке заполнения или явному `AutoMarkIncomplete`; dirty XML
обновляет эту отметку без сохранения. Это статическое состояние предпросмотра.

Автозаполнение панелей управляется Designer XML `Autofill`. При `false`
пустая табличная панель скрыта; изменение этого свойства в dirty XML обновляет
изображение без сохранения.

Изменение ширины колонки в несохранённом XML сохраняет заголовки и итоговые
ячейки таблицы, включая вложенные группы. Выбор колонки остаётся связанным
с исходным элементом формы. [Проверки Linux](measurements/t159-table-layout-identity-linux.json).

Пустые таблицы отображаются без выдуманных строк и значений. Поддержаны
шапки групп колонок `Horizontal`, `Vertical`, `InCell`, `ShowInHeader`, подвал
с локализованным текстом, `HeightInTableRows` и отметка незаполненной таблицы.
В Linux предпочтительная высота учитывает `Height`, ручной `MaxHeight`,
`AutoMaxHeight`, подвал и базовый шрифт таблицы. `HeightInTableRows` имеет
приоритет; автоматический максимум и ручной нулевой максимум не ограничивают
начальный размер. `Font` таблицы задаёт шрифт значений и заголовков колонок
по умолчанию; собственные `Font` и `TitleFont` переопределяют их независимо.

Добавлены статическая панель и навигация пустого динамического списка.
Ширины колонок табличной части учитывают длину номера строки и неограниченные
типы. Условия отбора относятся к `ViewStatusAddition`; их скрывает
`ViewStatusLocation=None`. У PDF условия отбора также обновляются из dirty XML.

на Linux в ru/en. Полная пиксельная приёмка, остальные виды динамических
списков и сочетания свойств остаются в работе.

Для остальных сложных полей добавлены native-образцы: дендрограмма, Гант,
сетка графической схемы, рамка географической схемы, поля текстового и PDF-документов
и трёхлетний выбор периода. Их размеры и основные состояния проверяются
в галерее из 20 полей. Локализация Ганта меняет переносы текста и видимость
нижних интервалов; это часть статического образца. Совпадение всех пикселей,
свойств оформления и вариантов размера ещё не подтверждено.

Числовое поле использует образец `0` из предпросмотра Конфигуратора.
Дата сохраняет региональные разделители, поля получают автоматические кнопки выбора.
Время по умолчанию использует 24-часовую маску независимо от языка IDE.
Явный 12-часовой шаблон в `EditFormat` сохраняет обозначение AM/PM.
Поле только времени по умолчанию отображается без кнопки календаря. `Visible=false` скрывает
элемент, `Enabled=false` и `ReadOnly=true` сохраняют белый фон поля и ослабляют
границу. Размеры ввода учитывают эффективный размер шрифта; на Linux проверены
10, 12, 14 и 16 pt. Отдельная галерея 15 состояний проходит в ru/en.
Другие гарнитуры, форматы и сочетания свойств требуют дальнейшей сверки.

Строковые поля различают обычный выбор с многоточием и режим списка со стрелкой.
`ListChoiceMode=true` сохраняет стрелку даже при `ChoiceButton=false`;
один список выбора без этого режима не добавляет кнопку. Пустое поле показывает
локализованный `InputHint`. При представлении подсказки кнопкой текст берётся
из `ToolTip` или `ExtendedTooltip.Title`, а знак вопроса занимает место рядом
с вводом. При пустом содержимом знак не добавляется. На Linux геометрия
проверена на 12 фиксированных полях с dirty XML и отдельным окном;
полная матрица оформления, многострочных полей и Windows ещё не принята.

Английские панели используют native-подпись `More actions` и отдельную
минимальную ширину: 429 px для обычной таблицы и 454 px для динамического списка
при стандартной панели поиска. Русские значения — 415 и 418 px.
Табличная галерея расширена до 16 случаев, включая скрытую колонку.

Группа без отображаемых потомков не занимает место в изображении, включая
собственные заголовок, фон и размеры. Исходные узлы остаются в дереве;
несохранённая правка видимости поля или колонки возвращает группу в изображение.
Это правило действует и для вложенных и сворачиваемых групп. На Linux проверена
21 native-форма, обновления dirty XML и отдельное окно с сохранением соседних
DOM-элементов и выбора. Полная приёмка таблиц и Windows остаётся открытой.

Командные панели с `HorizontalLocation=Right` прижимают кнопки к правому краю.
Автоматические панели распределяют свободную ширину по содержимому;
фиксированная панель слева сохраняет минимум. Правое размещение продолжает
занимать ширину даже при собственном `HorizontalStretch=false`; фиксированная
родительская группа ограничивает весь ряд. Пустые и скрытые панели не оставляют место. При
`United=false` панели участвуют в общих колонках соседних полей. Проекция
команд используется и при отображении, и при определении видимости;
исходные узлы остаются в дереве.

На Linux проверена точная геометрия 38 малых форм в ru/en, несохранённые
изменения, resize и отдельное окно. Повторный native-замер точного XML меню
`Actions` дал кнопку 77 px и рамку 111×79 вместо прежних 76 px и 142×79;
результат подтверждён при совместимости 8.3.24 и 8.3.27. Для явно заданных
меню и группы кнопок таблицы с `SearchStringLocation=None` также учтён
вертикальный отступ независимо от `Autofill`: в контрольных формах совпали
рамка 434×314 px, верх кнопок 39 px и сетки 74 px. Полный растр этих форм
и другие сочетания свойств продолжают проверяться. В мастере БСП «Далее»
перемещена с x=129 к x=628 при native x=625; рамки 814×612 и 812×612

На Linux `NormalSeparation` добавляет разделение между соседями и передаёт
его через вложенные группы. У двух соседних разделённых групп интервал
учитывается один раз; на внешнем краю колонки дополнительного отступа нет.
Окрашенная группа учитывает свой внутренний отступ. При `United=false`
общие строки получают наибольший интервал соседних колонок. Поддерживаются
явные интервалы `None`, `Half`, `Single`, `Double`; `None` сохраняет собственное
разделение группы. Сворачиваемая группа со скрытым заголовком не резервирует
место для кнопки раскрытия.

В наборе `native-group-separation` репозитория eska проверены 52 формы.
Размеры рамок и полей совпали с Конфигуратором в ru/en; dirty XML, resize
и открепление сохраняют DOM и выделение. Геометрия трёх форм БСП и «Выдачи
займа» сохранилась относительно предыдущей контрольной точки. Соседние
окрашенные группы, другие шрифты, native-resize и Windows требуют отдельной
приёмки. На Windows новый расчёт интервалов ещё не применяется; нативные
метрики нужно снять отдельно, затем повторить suite `group-spacing` в ru/en.

На Linux ширина надписей и заголовков рассчитывается по метрикам подключённой
гарнитуры с отдельным учётом слов и пробелов. Сохраняются явные переносы,
включая многострочный заголовок группы. `Width` задаёт ширину надписи;
при автоматическом размере `AutoMaxWidth` ограничивает перенос 400 px,
после чего используется ширина самой длинной полученной строки. Переразметка
работает в существующем цикле изменения размера формы. У гиперссылки учтена
дополнительная рамка 1 px, у декорации картинки — логический отступ 1 px.

У независимой вертикальной группы `NormalSeparation` (`United=false`)
собственное разделение не добавляется снаружи по вертикали. Интервал после
заголовка находится внутри группы: при `Auto` он составляет 9 px.
Разделение, запрошенное вложенной группой, сохраняется.

Надписи Liberation Mono различают перенос по ширине и явный перенос:
закрытая явным переносом строка получает дополнительный интервал.
Нормализация текста выполняется в одном месте; переразметка сохраняет
позиции переносов даже при одинаковых итоговой высоте и видимом тексте.
В проверенном Linux-профиле завершающий перенос в тексте с пробелами
закрывает последнюю строку, а в тексте без пробелов сохраняет пустую строку.

Эта сверка принимает рамки и поля, но не полный пиксельный профиль.
В контрольном Mono 10 pt глифы ещё находятся на 1 px выше native;
полная матрица шрифтов, другие контролы с Mono, native-resize, масштабы
и Windows требуют дальнейшей проверки. Геометрия трёх реальных форм БСП
и «Выдачи займа» сохранилась в 60 состояниях; полная native-сверка БСП
ещё открыта. На Windows suites `decorations` и `decoration-lines` проверяют
работу просмотра; для сравнения нужны собственные Windows-эталоны.

Обычные группы учитывают `TitleFont`, `Representation`, `ShowTitle` и
`BackColor`. Сильное разделение рисуется слева от содержимого; явный фон
добавляет отступы. По образцу Конфигуратора содержимое `Collapsed=true`
изначально развёрнуто. Заголовок позволяет свернуть и развернуть его локально.
Проверены страницы сверху, снизу и без вкладок, явная командная панель,
группа кнопок и меню первого уровня. Выбор пункта меню выделяет элемент
формы; BSL не исполняется. Вложенные меню ещё требуют сверки с платформой.

Галерея расширена до 22 случаев: добавлены `Auto`, боковые вкладки и `Swipe`.
В предпросмотре Конфигуратора Linux `Auto` и `Swipe` выглядят как вкладки сверху.
Размер группы учитывает все её страницы и сохраняется при переключении.
Выбор элемента дерева открывает содержащие его страницы в обоих окнах.
Если выбранная страница скрыта через dirty XML, показывается первая видимая;
возврат страницы восстанавливает прежний выбор. Это проверка геометрии и
взаимодействия; полное совпадение рамок, выделения и текста ещё не принято.

Linux-профиль использует измеренные рамку Конфигуратора, фон и шрифт
заголовка, трёхступенчатую тень и отдельный слой прямоугольного выделения.
Выделение не меняет размеры элементов. На собственном эталоне проверены
выбор корня, поля ввода и вкладки. Углы рамки и тени сверяются по пикселям
снимка VS Code на 24 размерах формы: 1248 пикселей ru/en совпали без масок.
[Результат проверки углов](measurements/t156-native-frame-corners-linux.json)
содержит точные области. После уточнения страниц обе страницы PagesAuto
целиком совпадают по 42 900 пикселям на локаль. Полная приёмка всех видов
форм и сочетаний свойств остаётся открытой.

Ширина боковых подписей на Linux округляется до ближайшего целого CSS-пикселя
по их содержимому. Это сохраняет кегль и устраняет дробное смещение соседнего
поля. У эталонов `Auto`/`Swipe` проверены точная ширина 271 px и координаты
обоих полей. Геометрия остальных сочетаний ещё требует полной приёмки.

Измеренные Linux-цвета по умолчанию: подпись поля и текст кнопки —
`#4d4d4d`, значение поля ввода — `#333333`. Значение ввода использует роль
`FieldTextColor`, подпись — `FormTextColor`; XML и выбранный стиль могут
переопределять их отдельно. Эталоны с крупным шрифтом проверяют цвет;
их полная геометрия ещё требует приёмки.

Для однострочного строкового ввода Linux общий расчёт учитывает длину строки,

## Нижняя командная панель

`CommandBarLocation=Bottom` размещает главную панель после полей формы.
При ограниченной высоте прокручивается область полей, а кнопки остаются
внизу. Панель учитывает выравнивание и доступную ширину. Справка из
`Help.xml` формы или объекта влияет на видимость кнопки «?».
Требуется Metadata API 1.44 для учёта этого признака.

На Linux размеры рамок и координаты измеренных полей и кнопок совпали
для 41 формы в каждой локали ru/en. Установленный VSIX также прошёл смену
`Top` ↔ `Bottom` и обновление справки из несохранённых XML в отдельном
окне. Повторный экспорт контрольных баз подтвердил сохранность исходников.
На форме БСП «Параметры администрирования программы» кнопки совпали при
трёх ширинах с одинаковой областью просмотра. При ширине 334 px поля адреса
и порта находятся на 7 px выше эталона. Предпочтительный размер этой формы
также требует дальнейшей сверки. [Замеры и квитанции проверок](measurements/forms-bottom-panel-linux-2026-11-09.json).

Для Windows-приёмки повторить замер нижней панели при 100% и аппаратном
DPI стенда. Включить выравнивание слева, по центру и справа, справку
формы и объекта, сужение с переходом команд в «Ещё» и короткую форму
с прокруткой. Проверить несохранённую смену положения панели в отдельном
окне и возврат в основную вкладку.
