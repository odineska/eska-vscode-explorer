# ESKA: 1C Explorer

Дерево метаданных Designer XML, свойства, запросы и BSL в VS Code / VSCodium.
Исходники остаются обычными XML, BSL и ресурсами проекта. Расширение использует
`eska-project`; платформа 1С для просмотра дерева не нужна.

[Полное руководство на сайте](https://odineska.github.io/eska/docs/) ·
[Практический пример с БСП](https://odineska.github.io/eska/docs/#practice) ·
[Справочник документации](https://github.com/odineska/eska-vscode-explorer/blob/main/docs/README.md)

Просмотр управляемых форм 1С 8.3.27 на SolidJS доступен как **beta**:
дерево, свойства, живое обновление XML и отдельное окно изображения.
В данных можно раскрывать ссылочные реквизиты; типы занимают одну строку.
Для поддержанных видов элементов свойства и события учитывают доступность
и значения по умолчанию, даже если
они отсутствуют в XML. Для поля с картинками значений показан кадр 0.
[Возможности и ограничения beta](https://github.com/odineska/eska-vscode-explorer/blob/main/docs/form-preview.md). Визуальная приёмка
продолжается; [функциональная приёмка Windows ru/en](docs/windows-forms-acceptance-2026-11-07.md) выполнена.
Выполнение BSL и графическое редактирование не входят в просмотр.

## Запуск и отладка 1С

`eska-debug` — собственный адаптер на Rust: DAP для редактора и HTTP для сервера
отладки 1С (`dbgs`). .NET не требуется. Доступны:

- запуск клиента с отладкой и подключение к работающим предметам;
- точки останова, условия, счётчики срабатываний, логпоинты и остановка по ошибке;
- шаги, стек вызовов, переменные, Watch, hover и свои выражения в Debug Console;
- раскрытие вложенных значений и изменение доступных переменных через **Set Value**;
- отладка конфигурации, подключённых расширений и внешних обработок EPF;
- отдельные профили `test` и `prod`, локальные базы, Distrobox и доступный по сети/VPN `dbgs`.

Настройки конкретного проекта хранятся в `.eska/settings_local.toml` вне Git.
В дереве каждого включённого проекта группа **Запуск и отладка** содержит
явные команды запуска, запуска с отладкой, подключения и обновления тестовой
базы, в том числе обновления с последующим запуском или отладкой.
Контекстное меню **Настройки проекта** содержит только **Настроить проект**.
Обновление базы средствами ESKA доступно только для `test`, включая поддержанные
частичные изменения и сценарий «обновить и запустить с отладкой».
Предпросмотр обновления показывает индикатор выполнения с отменой; сравнение
большой базы не ограничивается 30 секундами. Если backend подтвердил совпадение
исходников с существующей базой, Explorer не предлагает полный импорт.
Список изменений перед обновлением открывается в отдельной вкладке с прокруткой
без ограничения числа строк. Объекты и модули подписаны в обозначениях `eska diff`;
закрытие вкладки или отмена не применяют изменения.
После длительного сравнения исходники повторно проверяются на несохранённые
правки, включая сценарий без изменений базы перед запуском или отладкой.
Для `prod` доступны запуск с отладкой и подключение с проверкой исходников Git.
Нативный TCP-режим отладки 1С не поддерживается.

[Возможности и ограничения HTTP-отладки](https://github.com/odineska/eska/blob/main/docs/1c-http-debug.md) ·

## Explorer в работе

Четыре коротких скринкаста без звука — от настройки проводника до просмотра формы.
Записано на Linux: VS Code 1.144, Explorer 0.1.19 и ESKA 0.30.0.
Нажмите на GIF, чтобы открыть видео с управлением воспроизведением.

### 1. Настроить проводник

Перенесите ESKA: 1C Explorer наверх, сверните остальные группы и раскройте дерево проекта.

[![Настроить проводник — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11/explorer-setup.gif)](https://odineska.github.io/eska/docs/#demo-setup)

### 2. Найти объект и открыть модуль

Документ → реквизиты → табличная часть → модуль объекта BSL.

[![Найти объект и открыть модуль — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11/explorer-tree.gif)](https://odineska.github.io/eska/docs/#demo-tree)

### 3. Посмотреть свойства

Откройте свойства документа, найдите настройки номера и перейдите к исходному XML.

[![Посмотреть свойства — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11/explorer-properties.gif)](https://odineska.github.io/eska/docs/#demo-properties)

### 4. Открыть форму

Выберите поле на форме, раскройте данные и переключите страницы «Товары» и «Дополнительно».

[![Открыть форму — скринкаст без звука](https://raw.githubusercontent.com/odineska/odineska.github.io/main/assets/demos/2026-11/explorer-forms.gif)](https://odineska.github.io/eska/docs/#demo-forms)

Для дерева, свойств и статического просмотра форм платформа 1С не нужна.
**Текущий этап работы с формами — только просмотр; редактирование форм — в планах.**
Просмотрщик не исполняет BSL и команды формы.

## Возможности

- Ленивое дерево конфигураций, расширений, обработок и отчётов; поиск, переход
  от файла, сортировка, фильтры, файловые группы и Git-декорации.
- Типизированные свойства Designer XML, выбор типов и ссылок, изображения,
  проверенное переименование объектов и связанных исходников.
- Правила поддержки 1С и защищённый просмотр исходников.
- Отдельные SDBL-вкладки для запросов XML и BSL, восстановление черновиков,
  конструктор по образцу 1С с темой VS Code, пакетами, соединениями, итогами и UNION.
- Просмотр управляемых форм на SolidJS: дерево, свойства, реквизиты и команды,
  живое обновление XML и отдельное окно предпросмотра. Визуальная приёмка
  полного профиля 8.3.27 ещё выполняется. [Возможности и ограничения](https://github.com/odineska/eska-vscode-explorer/blob/main/docs/form-preview.md).
- BSL Analyzer: completion, hover, переходы, диагностика, подсказки параметров,
  безопасные правки; точное выравнивание многострочных аргументов.
- Форматирование BSL и запросов через `eska-fmt`, со стилем из `eska.toml`.
- Приложения workspace, внешняя база БСП из `~/.eska/lib`, отключение подпроектов
  с освобождением их индексов и единым выбранным языковым контекстом.
- Подготовка, проверка, обновление и восстановление управляемых компонентов.
- Локальные профили `test` и `prod` через контекстное меню «Настройки проекта»
  → «Настроить проект». Для каждого проекта ESKA хранит их в
  `.eska/settings_local.toml`. Для существующего Git-репозитория проверьте
  исключение этого файла. В поле пароля указывается имя переменной окружения.

## Быстрый старт

1. Установите VSIX **ESKA: 1C Explorer** в VS Code / VSCodium 1.109.0 или новее.
   Идентификатор — `1c-tooling.eska-explorer`; репозитории проекта — в `odineska`.
2. Установите `eska-project`. Общий CLI, Git и 1С для дерева необязательны.
   Для BSL нужен совместимый `bsl-analyzer-app`, для форматирования — `eska-fmt`,
   для отладки — `eska-debug`. Команда **Обновить все компоненты ESKA и BSL Analyzer** устанавливает
   отладчик и при обновлении старой установки. Нативные компоненты скачиваются
   отдельно и не увеличивают размер VSIX. Перед обновлением завершите сессии отладки ESKA.
3. Для существующей выгрузки без manifest выполните:

   ```sh
   eska-project init ./my-project --source src
   ```

4. Откройте папку с `eska.toml` в доверенном workspace и раскройте
   **ESKA: 1C Explorer**. При необходимости задайте абсолютные пути:

   ```json
   {
     "eska.explorer.executable": "/path/to/eska-project",
     "eska.explorer.analyzerExecutable": "/path/to/bsl-analyzer-app",
     "eska.explorer.formatterExecutable": "/path/to/eska-fmt"
   }
   ```

Пути относятся к машине проекта, включая Remote. Стандартные имена ищутся
в управляемой установке и PATH. Команда **Подготовить project, форматтер и
языковой компонент** помогает установить отсутствующие инструменты.
[Пошаговая настройка](docs/setup.ru.md) · [English setup](docs/setup.md).

Описание относится к текущим исходникам. Возможности согласуются по Metadata API:
минимум для дерева — 1.12; текущий API — 1.47. Совместимость старого backend
не означает доступность всех новых функций. [Контракты](https://github.com/odineska/eska-vscode-explorer/blob/main/docs/cli-management.md).

Библиотеки, группы подпроектов, подсказки и активность прошли
[повторную native-приёмку Windows в ru/en](https://github.com/odineska/eska-vscode-explorer/blob/main/docs/windows-review-2026-10-31.md)
на VS Code 1.144 и bsl-analyzer 0.4.2. macOS и VSCodium для активности
workspace требуют отдельной native-приёмки.

## Эталоны форм в тестах

Локальные тесты используют соседний checkout `../eska`. Другой каталог эталонов
задаётся абсолютным путём `ESKA_TEST_REFERENCE_ROOT`. Штатная подготовка CI
загружает исходники из точного тега установленного выпуска `eska-project`
в собственный каталог playground и передаёт этот путь последующим проверкам.
Существующий checkout разработчика не изменяется. Отсутствующие или не совпавшие
с тегом эталоны останавливают проверку; тесты визуального совпадения не пропускаются.
